1. Introduction

EMP is a role-based, server-rendered web application that manages oral/practical examinations end to end. An Admin creates courses and exams, defines a grading rubric and four date windows, assigns examiners and moves each exam through its lifecycle. Examiners (after Admin approval) publish time slots inside the slot-creation window and later score every rubric criterion for each student. Students register, search exams, book exactly one slot per exam inside the booking window, cancel before the deadline and finally see marks, a per-criterion breakdown and remarks once the Admin publishes results.

Core flow: Course → Exam (+ rubric, + examiners) → Slot Creation → Booking Open → Closed → evaluation → Completed → results published. Every action is a plain HTML form post or a link; JavaScript is used only for the optional charts on the Admin Reports page.

pip install -r requirements.txt
python app.py            # creates instance/app.db and the Admin on first start
# open http://127.0.0.1:5000      Admin login: admin@emp.com / admin123

The Admin is seeded in code on first start; there is no Admin registration page. Students register and are active at once; Examiners register as pending and cannot use the portal until the Admin approves them.

Security

  • Passwords stored only as Werkzeug hashes.
  • Flask signed-cookie session holds user_id, role, name.
  • role_req(role) guards each page: not logged in → login, wrong role → 403.
  • examiner_required also shows the “pending” page until the examiner is approved.
  • Object-level checks: examiner → own slots/students only (403); student → own bookings/results only (404).
  • All queries go through SQLAlchemy (parameterised); Jinja auto-escaping stays on.
  • State-changing actions are POST forms, never links.
  • Results are hidden (404) until the Admin publishes them.

6. Database design (ER diagram)

PK primary key · FK foreign key · UQ unique. Solid lines: parent → child inside the exam data. Dashed brown lines: references to users (examiner / student / acting admin). 1 = one, N = many. Every table also has a created_at column.

Relationships

  • One course has many exams.
  • One exam has many rubric criteria, slots, bookings and assigned examiners (exam_examiners, unique per exam + examiner).
  • One user with role examiner owns many slots; a user with role student has many bookings.
  • One slot has many bookings; bookings.old_slot_id remembers a reschedule.
  • One booking has many booking_history rows and at most one evaluation (booking_id unique).
  • One evaluation has one evaluation_scores row per rubric criterion (unique per evaluation + rubric).
  • Roles (admin, examiner, student) share one users table; status is active / pending / rejected / inactive.
  • Enums are stored as lowercase text; CHECK constraints guard marks, capacity, seats, time and date order.

Status lifecycles (stored in the status columns)

8. Testing

  • Manual walkthrough of the full story: register examiner (blocked) → Admin approves → course, exam, rubric, assignment → slots → two students book, the third is refused at capacity → evaluation → complete → publish → student sees results.
  • Scripted request-level checks (79 assertions, all passing): every page for every role, booking and seat counts, duplicate / full / clash refusals, cancel returns the seat, evaluation maths and range checks, 403 / 404 access rules, reschedule, change examiner, deactivation rule, profile and password changes.
  • Clean-install check: in a brand-new virtual environment pip install -r requirements.txt followed by python app.py creates the database and the Admin and serves every page.

9. Known limitations and future work

  • CSRF tokens (Flask-WTF) are not implemented yet; the secret key and default Admin password are development values and must be changed before real use.
  • The optional JSON API, PDF scorecard and e-mail notifications are not implemented. Lists are not paginated.
  • SQLite allows one writer at a time (fine for a local demo); times are stored as local time without a time-zone.
